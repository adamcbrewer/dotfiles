# Author Git Content

Before writing or revising the text, call the Skill tool with `my-voice`. Apply its tone and language to the content; use the repository's format and templates for structure rather than its email conventions.

- Ground the text in the actual change, discussion, or ticket. Do not invent facts, test results, decisions, or promises.
- Keep titles and commit subjects concise and specific. Follow repository conventions and required templates; retain issue references and technical terms exactly where needed.
- Default commit subjects and PR titles to third-person present tense, such as "Prevents duplicate emails", "Keeps draft replies", or "Clears the selected customer", rather than imperative wording. Follow an explicit repository convention or user instruction when it requires a different form.
- Write supplied software versions as `vX.X.X`, such as `v4.2.0`, rather than "app version 4.2.0". Preserve the supplied version's precision and any prerelease or build suffix; never invent missing components.
- Use natural, direct prose for descriptions and comments; short, useful summaries for titles and commit subjects.
- If Adam explicitly asks for a different voice, follow that request.
